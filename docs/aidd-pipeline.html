PHASE 2 仕様書生成 逐次
skill: feature-spec
調査結果を feature-spec スキルで SPEC.md に集約。
Part 1（人間向け要件・受け入れ条件）+ Part 2（AI向け技術詳細・並列グループ宣言）の2部構成。

複雑設計・DBスキーマ変更・高リスク機能の場合は workflow: spec-deep-validate を実行後に停止①へ。
⚠️
停止① — Human Checkpoint
仕様レビュー（Part 1 提示・承認待ち）
人間が SPEC.md Part 1 を承認するまで Phase 3 へ進まない。
Part 2 は「技術詳細なのでレビュー不要」と伝える。

PHASE 4 統合ゲート 親が逐次
🔧 親（または implementer × 1）
各グループの成果を 親が1人で結線（共有ファイルに触るのはここだけ）。
npm test + npm run lint を回して 全緑 を確認。
競合・重複・宣言外のファイル変更がないかを検証。
