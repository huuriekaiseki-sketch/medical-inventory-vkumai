# 取りこぼし台帳（E-xxx）

**すり抜けた 1 件 = 1 行。** ルールブックに書いた「限界」が的外れかどうかは、書いた時点では分からない。
分かるのはテストやレビューで漏れが出たときだけなので、その漏れをここへ戻して限界とルールを育てる。

```
実装 → 検査 → 漏れが出る → ここに 1 行 → ルールブック・実装・テストを直す → 再検査 → 解決済み
```

**緑になっても終われない。** `未分類` の行が 1 つでもあると `npm test` が落ちる
（`scripts/lib/__tests__/escaped-defects.test.ts`）。実装を直して他が全部緑になっても、
分類していない漏れが残っている限りスイートは赤のまま。

- 落ちた検査は `scripts/record-test-failure.sh`（PostToolUse）が下書きとして
  `logs/escape-candidates.jsonl` に拾う。**判定はしない**（実装途中の RED は漏れではない）。
- 下書きを見ないまま終わろうとすると `scripts/check-escape-ledger.sh`（Stop）が聞く。
  該当なしなら `bash scripts/triage-escapes.sh --none "理由"` で記録する（黙って消す道は無い）。

## 更新ルール

- 列は固定 9 列: ID / 何が起きたか / 分類 / 何が見つけたか / 関連ルールブック / 誰が値を決めたか /
  直したこと / 再発防止 / 状態。列の中に `|` を書かない。
- ID は `E-` + 3 桁。区分ごとに 10 刻み（権限・認可 01x / 記録・監査 02x / 検査の運用 03x）。
- **分類**は 4 語のみ: 実装バグ / テスト不足 / ルールブック不足 / 環境。
  `ルールブック不足` を選んだら、関連ルールブックの行と `## 限界` を直すまで `解決済み` にしない。
- **何が見つけたか**（検出源）は下の語彙から選ぶ。**独立性は検出源から決まる**ので行ごとに書かない。
- **誰が値を決めたか**: `domain_owner` / `security_review` / `product_owner` /
  `AI 提案（人が承認）` / `AI 提案（未承認）` / `該当なし`。
  上限・権限・保持期間・可視範囲のように**値を決めた**行では必須。
  `AI 提案（未承認）` が多い箇所は、ルール・実装・テストが同じ生成元に依存している合図。
- **再発防止**列にはバッククォートでパスを書く。`解決済み` の行はここが必須
  （`scripts/lib/check-catalog.mjs` が状態と突き合わせ、パスの実在も見る）。
- 状態は 4 語のみ: 未分類 / 対応中 / 解決済み / 該当なし。

## 検出源と独立性

「独立」とは手段の名前ではなく、**ルール・実装・テストと別の前提から来ているか**で決まる。
DB 制約と RLS が同じ誤った前提から作られていれば、両方が緑でも独立ではない。

| 検出源 | 独立性 | なぜ |
| --- | --- | --- |
| 3A テスト | 同源 | ルールブックから書くので、ルールが間違っていれば期待値も間違う |
| DB 制約 | 条件つき | 別の場所で守るが、前提はルールブックと同じことが多い |
| RLS | 条件つき | 同上 |
| 層間突合 | 条件つき | ずれは見つかるが、全層が同じ思い込みなら揃って通る |
| ミューテーション | 独立 | テストの検知力そのものを測る。期待値の正しさには依存しない |
| 実経路攻撃 | 独立 | 実装の意図ではなく、外から実際に起きることを見る |
| 人の判断 | 独立 | 唯一、生成元が違う |
| 実運用 | 独立 | 同上。ただし気づくのが最も遅い |

## 読み方

まず `未分類` と `対応中` を見る。次に **`誰が値を決めたか` が `AI 提案（未承認）` の行**を見る。
そこはルール・実装・テストが同じ生成元に依存していて、揃って間違える余地が残っている。

`何が見つけたか` を数えると、投資先が分かる。

- **3A テストばかり**が見つけている → 独立根拠（ミューテーション・実経路・人のレビュー）が足りない
- **独立根拠ばかり**が見つけている → 3A の書き方が甘い。ルールブックから期待値を写すだけになっていないか
- **人の判断ばかり**が見つけている → 機械の検査が届いていない領域がある

**機械が自力で見つけたのは E-032 の 1 件だけ**（マージ後に 4 軸の突合が捕まえた）。

## 限界

- **分類は自己申告のまま。** 機械が強制できるのは「分類を書いたか」までで、その分類が正しいかは
  判定できない。`環境` を選べば何でも通せる（同じテストで `環境` が続くならフレーキーの合図）。
- **Bash 以外で気づいた漏れは自動で拾えない。** レビューでの指摘・実運用での発覚は手で足すしかない。
  2026-09-07 の 3 件のうち 2 件がこれで、機械は 1 件も拾っていない。
- **「見つけた」と「起きていた」は違う。** ここに載るのは気づいたものだけで、
  まだ誰も気づいていない漏れは 1 行も載らない。件数の少なさを健全さの証拠に読まないこと。
- **下書きから台帳へ移す一歩は止められない。** `npm test` が止めるのは「台帳に未分類がある」状態で、
  「そもそも台帳に書かない」ことは止められない（Stop hook が聞き続けるだけ）。
