# 乗っ取り後の到達範囲（B-xxx）

正規の資格情報が漏れた前提で、その立場が**どこまで届き**、**何が痕跡に残り**、**何が止めるか**を
立場ごとに測った表（issue #757 の 39）。脅威モデル（`threat-model.md`）が「誰が・どこから」を
書くのに対し、ここは「入られた後、どこまで広がるか」を数字と実測で書く。
アクセス経路の棚卸し（`access-path-inventory.md`）が鍵の所在、ここが鍵ごとの被害。

## 更新ルール

- 列は固定 7 列: ID / 立場（持っているもの） / 読める範囲 / 書ける範囲 / 痕跡（検知） / 止めるもの / 状態。列の中に `|` を書かない。
- ID は `B-` + 3 桁。区分ごとに 10 刻み（利用者の資格情報 00x / 運用の鍵 01x / 開発・配布の経路 02x）。欠番は詰めない。
- 状態は 4 語のみ:
  - 限定済み: 範囲が意図した広さに収まっていて、それを守る実測テストがある
  - 広い（意図）: 広いが設計としてそう決めた。理由を「読める範囲」か「止めるもの」に書く
  - 要縮小: 広すぎる。`#757-N` を必ず書く
  - 未測定: 測っていない。`#757-N` を必ず書く
- 「止めるもの」列はバッククォートでテスト・仕組みのパスを書く。無い行は `未`。
  `scripts/check-blast-radius.test.sh`（CI `hooks-test`）が列数・ID・状態・パスの実在・
  「限定済み」のテスト必須・`#757-N` の有無を検査する。
- **更新の引き金**: 新しい鍵・ロール・外部連携の追加、RLS ポリシーの緩和、テナント数の桁が変わったとき、
  実際のインシデント。

## 読み方

- **B-001 は測って見つけ、塞いだ**。パスワード 1 つで全施設の患者情報が読め、痕跡も残らなかった。
  20260907000001 で施設スコープ 10 表と `audit_log` の SELECT、admin の集計 RPC に `has_aal2()` を足した。
  費用は小さい: `has_aal2()` は verified な TOTP factor を持たない利用者に TRUE を返すので
  **MFA 未登録の利用者は影響を受けず**、MFA 登録済みの利用者は proxy.ts が保護ページに入る前に
  aal2 まで昇格させるので画面の見え方も変わらない（aal1 のまま描画される /login・/mfa-challenge・layout は
  施設スコープの表を読まない。実測）。
- **残っているのは「読んだ痕跡が無い」こと**。aal2 を要求しても、読み取りは `audit_log` に来ない。
  「いつ誰が見たか」は #757-24 が要る。B-004（TOTP まで奪われた場合）はこの穴がそのまま残る。
- **B-003 は実測で見つけて塞いだ**。設計上は #623 で「業務データの書き込みには TOTP が要る」と
  決めていたが、マスタ 4 表が漏れていた。カタログの行を読むだけでは気づけず、実 DB で測って分かった。
- **書き込みは全て `audit_log` に残る**（B-003・B-004・B-010）。読み取りはどの立場でも残らないので、
  「いつ漏れたか」は今のところ答えられない（#757-24）。読み取りを aal2 で狭めても、
  この「答えられない」は変わらない。
- **テナント非分離が設計のもの**（施設の一覧・商品マスタ・価格履歴）は aal1 でも読める。
  患者情報を含まないという判断で、締めるなら別の判断として行う（20260907000001 の対象外の節）。

## 限界

- **実測したのは aal1 の admin だけ。** 他の立場（漏れた service role キー・
  乗っ取られた CI・Supabase アカウント）は、経路を読んだ判断で書いている。
  **実際に鍵を漏らして試すことはできない**ので、ここは推定のまま残る。
- **「限定済み」は今の実装での話。** 新しい経路が増えれば範囲は広がるが、
  この表が自動で追従することはない（[`access-path-inventory.md`](./access-path-inventory.md) と同じ）。
- **痕跡（検知）の列は「残る」までしか言っていない。** 残った痕跡を誰かが見る仕組みは
  #757-8（監視・アラート）の担当で、まだ無い。**痕跡が残っても気づかれない**状態。
- **ダッシュボード側（Vercel / Supabase / GitHub）の権限は棚卸ししていない**（#757-35・#757-36）。
  そこを握られたときの範囲は、この表では測れていない。
