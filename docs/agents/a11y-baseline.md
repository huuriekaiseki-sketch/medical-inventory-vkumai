# 画面の操作性の基準（a11y-baseline）

病院のスタッフが業務で毎日使う画面が、キーボードだけの操作・拡大表示・読み上げで
使えるかを機械で測る（issue #757 の 20）。

## 使い方

```bash
npx playwright test e2e/a11y.spec.ts
```

判定は WCAG 2.1 の A / AA（`wcag2a` / `wcag2aa` / `wcag21a` / `wcag21aa`）。
**serious / critical だけ**を失敗にする。moderate / minor は現在 0 件で、増えたら止まる。

## 初回計測（2026-09-07）

7 画面を測り、違反は **色のコントラストの 1 種類だけ**だった。
`img-alt` や `label` のような構造の欠陥は 1 件も無い。

見つかった配色は 4 つ。うち 1 つはその場で直した。

| 配色 | 比 | 必要 | 扱い |
| --- | --- | --- | --- |
| `#ff5f03` の文字 on `#edeade` | 2.6 | 4.5 | **直した**（`#b03f00` へ。比 4.90） |
| 白文字 on `#ff5f03` の地色 | 3.04 | 4.5 | **直した**（地色を `#b03f00` へ。比 5.90） |
| `#6b7280` の文字 on `#edeade` | 4.01 | 4.5 | **直した**（`#4b5563` へ。比 6.27） |
| `#9ca3af` の文字 on `#ffffff` | 2.53 | 4.5 | **直した**（`#6b7280` へ。比 4.83） |

### 直した分（ブランド色の文字）

見出しの上に出る小さなラベル（`Settings & More` など）に、ブランド色のオレンジを
そのまま使っていた。人が「文字のときだけ濃くする」と決め、17 ファイル・18 箇所を
`#b03f00` に置き換えた。このときは**背景色・罫線としての `#ff5f03` は残した**が、翌 2026-09-08 に地色も直したので src から消えた（下記）。

再発は `scripts/check-text-contrast.test.sh`（CI `hooks-test`）が止める。

**やり直した経緯**: 最初 `#c24500`（白背景で比 5.07）に変えたが、実測すると比 4.2 でまだ
足りなかった。**この製品の地色は白ではなく `#edeade`** で、白前提の計算が間違っていた。
axe が出す実測値（前景・背景・比）を失敗メッセージに含めるようにして特定した。

### 残り 3 つも直した（2026-09-08）

人が「3 つとも直してよい」と判断したので、同日に置き換えた。**例外は 0 件になった。**

| 配色 | どこ | 直した値 | 比 |
| --- | --- | --- | --- |
| 白文字 on `#ff5f03` | ボタン・バッジの地色（12 箇所） | `#b03f00` | 5.90 |
| `#6b7280` on `#edeade` | 本文の灰色 | `#4b5563` | 6.27 |
| `#9ca3af` on `#ffffff` | 補足文 | `#6b7280` | 4.83 |

**41 ファイル・155 箇所**を置き換えた。`#ff5f03` は src から 1 つも無くなった
（このリポジトリでこの色の上に乗るのは**必ず白文字**で、地色として置いた時点で比が 3.04 になる）。

**残した例外**: 無効化ボタンの地色 `#9ca3af`（`OrderButtons.tsx`）。
無効化された操作は WCAG のコントラスト要件の対象外で、axe も飛ばす。

**測り直した結果**: 7 画面すべてで serious / critical の違反 **0 件**、例外 **0 件**。
`e2e/a11y.spec.ts` の `PENDING_CONTRAST` と `PENDING_COUNT` は空にした。
**空なので、同じ配色が戻ってきたら即座に失敗する。**

再発は `scripts/check-text-contrast.test.sh`（CI `hooks-test`）が書いた瞬間に止める
（文字色としての `#ff5f03` / 地色としての `#ff5f03` / 文字色としての `#9ca3af` の 3 つ）。
実測の正本は E2E のほうで、シェルの検査は**速い前置き**。

## ページ別の判断待ちの場所の数（2026-09-08 実測）

**全画面 0 件。** 判断待ちを 3 つとも直したので、例外として数える場所が無くなった。

直す前は次のとおりだった（数えるのは「場所」であって「画面に出ている個数」ではない。
配色 + タグ + class + style の署名で重複を潰すので、一覧が何行あっても同じ書き方なら 1 か所）。

| 画面 | 直す前 | 直した後 |
| --- | --- | --- |
| `/products` | 2 | 0 |
| `/categories` | 1 | 0 |
| `/distributor-products` | 2 | 0 |
| `/news` | 1 | 0 |
| `/facilities` / `/hospital-prices` / `/other` | 0 | 0 |

### なぜ数え方を変えたか（2026-09-08）

以前は axe が返したノードを 1 件ずつ数えていたので、**一覧の行が増えるだけで数が増えた**。
`/news` は 1 行につき 1 か所（日時の薄い灰色）を出すため、手元の DB に製品が増えると数が増え、
基準 12 に対して 20 になって落ちた。**コードは 1 行も変わっていない。**

消せない・積み上がるデータでテストが壊れる形は E-022（拒否記録の山）・E-023（監査ログの行数）と
同じで、**これが 3 回目**。見たいのは「同じ配色が新しい**場所**に増えていないか」なので、
行数に依存しない単位に変えた。あわせて基準を実測し直した
（`/distributor-products` は 3 → 2、`/news` は 12 → 1。基準を 0 にして出た値をそのまま入れている）。

## 起動の引き金

E2E なので `npm run test:e2e` と、main への push 後の CI で回る。
PR 段階では手元で実行する（`docs/agents/common.md` の E2E 実行ルールと同じ）。

## 更新の引き金

- 新しい画面を足したとき（`e2e/a11y.spec.ts` の `pages` に行を足す）
- 配色を変えたとき（判断待ちの表を見直す）
- 新しい判断待ちを作りたくなったとき（**例外は 0 件が既定**。増やすなら人が決める）
