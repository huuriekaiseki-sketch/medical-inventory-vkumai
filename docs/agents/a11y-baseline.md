# 画面の操作性の基準（a11y-baseline）

病院のスタッフが業務で毎日使う画面が、キーボードだけの操作・拡大表示・読み上げで
使えるかを機械で測る（issue #757 の 20）。

## 使い方

```bash
npx playwright test e2e/a11y.spec.ts
```

判定は WCAG 2.1 の A / AA（`wcag2a` / `wcag2aa` / `wcag21a` / `wcag21aa`）。
**serious / critical だけ**を失敗にする。moderate / minor は現在 0 件で、増えたら止まる。

## 初回計測（2026-09-07）

7 画面を測り、違反は **色のコントラストの 1 種類だけ**だった。
`img-alt` や `label` のような構造の欠陥は 1 件も無い。

見つかった配色は 4 つ。うち 1 つはその場で直した。

| 配色 | 比 | 必要 | 扱い |
| --- | --- | --- | --- |
| `#ff5f03` の文字 on `#edeade` | 2.6 | 4.5 | **直した**（`#b03f00` へ。比 4.90） |
| 白文字 on `#ff5f03` の地色 | 3.04 | 4.5 | 判断待ち |
| `#6b7280` の文字 on `#edeade` | 4.01 | 4.5 | 判断待ち |
| `#9ca3af` の文字 on `#ffffff` | 2.53 | 4.5 | 判断待ち |

### 直した分（ブランド色の文字）

見出しの上に出る小さなラベル（`Settings & More` など）に、ブランド色のオレンジを
そのまま使っていた。人が「文字のときだけ濃くする」と決め、17 ファイル・18 箇所を
`#b03f00` に置き換えた。**背景色・罫線としての `#ff5f03` はそのまま。**

再発は `scripts/check-text-contrast.test.sh`（CI `hooks-test`）が止める。

**やり直した経緯**: 最初 `#c24500`（白背景で比 5.07）に変えたが、実測すると比 4.2 でまだ
足りなかった。**この製品の地色は白ではなく `#edeade`** で、白前提の計算が間違っていた。
axe が出す実測値（前景・背景・比）を失敗メッセージに含めるようにして特定した。

### 判断待ちの 3 つ

どれも**見た目が変わる判断**なので、人が決めるまで例外として `e2e/a11y.spec.ts` の
`PENDING_CONTRAST` に置く。件数は `PENDING_COUNT` で固定してあり、同じ配色でも
**件数が増えたら失敗する**（新しい場所に増やさせない）。

| 配色 | どこ | 直すと何が変わるか | 直し方の案 |
| --- | --- | --- | --- |
| 白文字 on `#ff5f03` | 主要ボタン（4 画面で 4 箇所） | ボタンの色が濃くなる。画面の印象がいちばん変わる | 地色を `#b03f00` にする（白文字との比 5.90） |
| `#6b7280` on `#edeade` | 本文の灰色（38 ファイル） | 全画面の本文が少し濃くなる | `#4b5563` にする（比 6.27） |
| `#9ca3af` on `#ffffff` | 補足文（3 ファイル） | 補足文が少し濃くなる | `#6b7280` にする（比 4.83） |

**この表から行を消すと、その配色は自動的に検査で止まるようになる。**

## 起動の引き金

E2E なので `npm run test:e2e` と、main への push 後の CI で回る。
PR 段階では手元で実行する（`docs/agents/common.md` の E2E 実行ルールと同じ）。

## 更新の引き金

- 新しい画面を足したとき（`e2e/a11y.spec.ts` の `pages` に行を足す）
- 配色を変えたとき（判断待ちの表を見直す）
- 判断待ちの 3 つのどれかを人が決めたとき（直して表から消す）
