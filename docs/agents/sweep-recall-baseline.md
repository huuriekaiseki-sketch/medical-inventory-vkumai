### 訂正: 「安定して外す」と書いたが、`sweep-db` は振れていた

`sweep-db` は**条件を変える前に 5 回、今の条件で 1 回**、合計 6 回連続で case-1 を外していた。
そこから「安定して外す」と書いたが、**7 回目（今の条件の 2 回目）で当てた**。
安定して外すのではなく、**当たりにくいが当たることもある**——つまり振れている。

**1 回多く測ったから訂正できた。** 「2 回では『安定』と言い切るには弱い」と自分で書いた限界が、
そのまま現実になった例。

今の条件で言えるのは **2 回中 1 回当たり**まで。

### いま言えること / 言えないこと

**言える**:

- `sweep-types` と `sweep-ui` は 2 回とも同じケースを外した（ただし 2 回では「常に」とは言えない）
- `sweep-data` と `sweep-db` は同じ条件で結果が変わる——**1 回の結果を合否に使えない**

**言えない**:

- どの層も「必ず外す」「必ず当てる」——2 回では足りない
- 層どうしの優劣——fixture の難易度が揃っていない

- **外し続ける型の欠陥は、機械の検査へ寄せる。** 実際にこの日 2 つ寄せた
  （`check-definer-authz-gaps` / `check-suspense-gaps`）
- `sweep-data` のように振れる層は、**1 回の結果で良し悪しを言わない**

## 限界

- 各層 2 回ずつ。2 回では「安定」と言い切るには弱い（3〜5 回が望ましい）
- 「実コードへの指摘」の件数は**本物か誤りかを分けない**。分けるのは人の仕事
- 件数が読めない回がある（エージェントが契約どおりの `FINDINGS: <件数>` を返さない）。
  0 件と混ぜず `findingsUnreadable` に分けてある

**7 本すべてが通った。** ところが調べると、捕まえるはずの仕組みは**存在していた**——
`e2e/api-cross-facility-attack.spec.ts` の「攻撃表は実在する route と過不足なく対応する（ratchet）」。
これは `src/app` 配下を実際に列挙して攻撃表と突き合わせる、正しい逆向きの検査だった。

**動いていなかった理由は 2 つ**:

1. E2E は main マージ後にしか回らない（PR 実行は 2026-08-25 に廃止。E-060）
2. 同じ `test.describe` 直下の `test.skip` 2 つ（cross-facility フィクスチャ /
   `SUPABASE_SERVICE_ROLE_KEY`）が**この ratchet にも効いていた**。
   ratchet はファイルを読むだけで DB も鍵も要らないのに、
   スナップショット比較の前提に巻き込まれて、**Supabase を止めている間ずっとスキップ**されていた

**スキップは失敗ではないので、レポート上は緑と同じ色で出る。**
「何本が実行されなかったか」を数える習慣が無いと、誰も気づかない。

対応:

- 突合を `e2e/api-route-registry.ts` の純粋関数として切り出し、
  `src/__tests__/api-attack-matrix-ratchet.test.ts` から **`npm test` で毎回**回す
  （判定は 1 か所にしか置かない。E-053）
- 列挙の抜け道（`route.tsx`・`export const GET`・`export { h as GET }`）も同時に塞いだ
  （実測では今のところ全 34 本が `route.ts` + `export async function`。**0 件のうちに塞ぐ**）
- 同じ形が他に残っていないかを機械で見る検査を新設（`scripts/check-skip-scope.test.sh`、C-033）。
  実測: spec 16 本 / describe 24 / 条件つき skip 27 に対し違反 0 件。
  修正前の spec を入力にすると**ちょうど 1 件**を名指しする（対照）

**教訓**: 「誰も捕まえない」と「捕まえる仕組みはあるが動いていない」は、
**外から見た症状が同じ**（欠陥を置いても緑）。
仕組みが無いと決めつけて新しく作る前に、**あるはずのものがなぜ黙っているか**を先に見る。

**教訓**: 見逃しを見つけたら、次に測るのは「ほかに何が捕まえるか」。
そこを測らずに検査を足すと、**既にあるものを作り直す**。
実際 sweep-types は「機械化できるはず」と考えて調べ、**既に落ちていた**ので作らなかった。
