# 検査の引き出し（security-test-catalog）

**これはルーチンの一覧ではない。** 「こういう検査がある」を保存しておき、引き金が来たときに開ける引き出し。
毎回回すもの・変更時に回すものは [`test-matrix.md`](./test-matrix.md) が正本で、守る約束は
[`promise-catalog.md`](./promise-catalog.md)、着手順は issue #757。本ファイルはその外側にある観点を、
「いま要るか」「何が起きたら要るか」と一緒に置く。2026-09-06 に Codex のレビュー（7 回分、約 90 観点）を
整理して初版を作った。

## 枠組み

検査は次の **5 保証**のどれかに属する。個別項目を増やすより、機能ごとにこの 5 つが揃っているかを見る。

| 記号 | 保証 | 問い |
|---|---|---|
| A | 変更しても壊れない | 実装・設定・依存・モデルを変えたとき、拒否条件と不変条件がそのまま残るか |
| B | 検知できる | 侵害・誤操作・異常が起きたとき、人が気づく信号が出るか |
| C | 止められる | 危険な経路を、部分的に・即座に・波及させずに止められるか |
| D | 戻せる | 復元・ロールバック・鍵交換のあと、権限と証跡まで元に戻るか |
| E | 説明できる | 誰が・どの経路で・何を判断したかを後から第三者に示せるか |

機能ごとに揃えるのは **4 種類**: ①正常に動く ②攻撃されても拒否する ③障害時に安全側へ倒れる ④後から証明・停止・復旧できる。

## 状態の読み方

| 状態 | 意味 |
|---|---|
| 実装済み | 毎回か変更時に機械で回っている。守るテスト・hook・ratchet がある |
| 計画 #757-N | ロードマップの N 番として着手予定 |
| 引き金付き | いまは要らない。「引き金」列の出来事が起きたら開ける |
| 対象外 | この製品に該当する機能・条件が無い。理由を書く |

**引き金の書き方**: 機能の追加（決済・Webhook・ファイル受け取り）、事故、外部公開、利用者数の節目、
定期（月次 docs 差分・四半期訓練）のいずれかで書く。「いつか」は書かない。

- 新機能・新しい外部連携・事故・外部公開のいずれかが来たら、この表の「引き金」列を上から読み、当てはまる行を
  #757 の番号付き項目に昇格させる（昇格したら状態列を「計画 #757-N」に書き換える）
- 昇格した検査は必ず test-matrix の行（毎回 / 変更時 / 節目 / 一度きり）か約束カタログの ID になる。
  ここに置いたままでは動かない
