## 00 目的・影響範囲・対象外
- 目的: 「lock を生成する道具の版が誰にも固定されていない」状態をなくす
- 対象外: `engine-strict` による強制 / Corepack / `packageManager` フィールド
- 依存の変更: **パッケージの追加・更新・削除は無し**。`package.json` に `engines` を足しただけ

## 何が起きていたか

2026-09-18、CI の全ジョブが冒頭の `npm ci` で落ちた。

```
npm error `npm ci` can only install packages when your package.json and package-lock.json are in sync.
npm error Missing: @emnapi/runtime@1.11.3 from lock file
```

**手元の npm 11.6.2 は「lock は最新」と言い、CI の npm 11.19.0 だけが落とした。**

原因は CI が `node-version: '24'`（浮動）だったこと。Node のパッチが上がるたびに同梱 npm も動く。
実測: 手元 node 24.11.1 / npm 11.6.2、CI node 24.20.0 / npm 11.19.0。

## 02 内部でどう守っているか
- `.nvmrc` = `24.20.0` が**唯一の正本**。同梱 npm が決まるので npm も自動的に揃う
- `package.json` の `engines` は宣言（`node: 24.20.0` / `npm: 11.19.0`）
- CI の **7 箇所すべて**が `.nvmrc` を参照する
- `scripts/check-node-version-pin.test.sh` が 3 つを見る:
  (a) `.nvmrc` が厳密な版（`x.y.z`）か (b) `engines.node` と一致するか
  (c) **すべての workflow が浮動の `node-version` を書いていないか**

### なぜ `24.20.0` か
CI が現在解決している版であり、**いま main に入っている lock を生成した npm 11.19.0 が同梱される**版だから。
別の版にすると、コミット済みの lock と食い違う。

### なぜ `engine-strict` を入れないか
入れると版が違う手元で `npm ci` が失敗し、作業が止まる。
Node を上げれば揃う前提なので、止めるほどの強制はしない。食い違ったままなら CI の `npm ci` が落ちるので、
黙って通ることは無い。

## 05 何かあったらどうするか
- Node を上げるとき: `.nvmrc` と `engines.node` を同時に直す（検査が食い違いを落とす）。
  `engines.npm` は**その Node に同梱される npm** に手で合わせる（版の対応表は持っていない）
- 異常の判断基準: CI で `npm ci` が EUSAGE で落ちる → lock を生成した npm と CI の npm が食い違っている
- ロールバック: revert のみ

## 後任AIへの注意
- **`node-version: '24'` のような浮動指定に戻さない。** npm の版まで一緒に動く（検査が落とす）
- **`engines.npm` が実際にその Node に同梱される npm かは機械で確かめていない。** Node を上げたら手で直す
- **導入先に配る検査は、自分のリポジトリではなく回された先の木を見る。** `CLAUDE_PROJECT_DIR` を優先すること
