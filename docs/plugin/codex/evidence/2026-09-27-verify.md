## Codex CLI での実測と停止理由

1. 検証用リポジトリで Codex CLI を起動。初回は検証用ディレクトリを信頼したが、hook は「Continue without trusting」を選択した。2回目も同じ状態を確認した。ChatGPT desktop app の再起動や CLI の更新はしていない。
2. `/hooks` は PreToolUse 3件、SessionStart 1件を表示。PreToolUse は個人 `~/.codex/hooks.json` 1件、別プラグイン `claude-mem` 1件、別プラグイン `hookify` 1件。SessionStart 1件は `claude-mem`。`aidd-codex` 由来の hook はどちらの一覧にも無かった。
3. 画面の「2 hooks need review」は `claude-mem` など既存の別 hook に関するもの。本プラグインの信頼対象が表示されなかったため、他の hook を信頼せず終了した。
4. `codex features list` では `hooks stable true`、`plugins stable true`、`plugin_hooks removed false` と表示された。これと不読込との因果関係は未確認。Codex CLI が manifest を受理したかどうかも確定していない。

プラグインの存在と有効化は確認できたが、対象 hook がランタイム一覧に無い。仕様書 §4 の信頼前後比較へ進めないため、その場で停止した。

## 中心リポジトリの検査

- `bash scripts/build-plugin.sh` で配布物を再生成し、`bash scripts/build-plugin.sh --check` は **295 ファイル一致**。KNOWN-LIMITS の生成物と manifest の hash を更新した。evidence は現行の生成規則では配布物に入らない。
- 指定された `for t in scripts/*.test.sh scripts/lib/*.test.sh; do bash "$t" || echo "FAIL $t"; done` を全件実行。通常権限での完走結果は `FAIL scripts/check-layer-consistency.test.sh` の1件。失敗ログは、作業パスの `雑談` が `%E9%9B%91%E8%AB%87` に変換され、Node が `scan-db-constraints.mjs` を見つけられないもの。今回変更したファイルは文書とその生成物のみで、このテスト・判定器は変更していない。原因の修正は段階 (4) の対象外。
- 最初の制限環境でのループはローカル `127.0.0.1` 待受が `EPERM` になる検査があったため途中で止め、通常権限で全件再実行した。CI 成功の代替とは扱わない。
- `git diff --check` と配布物の `--check` は成功。PR の GitHub CI は作成後に対象 commit で確認する。

## 切り分け追試と信頼後の実発火

### manifest の一変数実験 C'

CLI は `0.147.0` のまま。個人の configured marketplace `aidd-codex-configured` で、`.codex-plugin/plugin.json` のトップレベル `"hooks": "./hooks/hooks.json"` と、それ以外の配布ファイルを固定した。退避済みのルート `plugin.json` から `$schema` / name / version / description だけを戻し、`extensions` は入れなかった。各構成で `codex plugin remove` → `add` を行い、検証用リポジトリの新規 CLI で `/hooks` を確認した。

| 構成 | PreToolUse | SessionStart | aidd-codex の4本 |
| --- | --- | --- | --- |
| 候補C: `.codex-plugin/plugin.json` のみ | 4本（うち新規1本） | 4本（うち新規3本） | 信頼待ちとして表示 |
| C': 同じ構成にルート `plugin.json` を追加 | 3本 | 1本 | 表示なし |

C' の結果から、この CLI と marketplace の条件では**ルート `plugin.json` の存在が hook の認識を妨げる**と分かった。`extensions` を抜くだけでは解消しない。検証後はルートを再び外して候補Cに戻し、再インストールした。`plugin_hooks` は `removed false` のままで、候補Eのフラグ変更と候補Bの CLI 更新はしていない。生成器への反映は別 PR の判断事項。

### 二重導入の解消と信頼

旧 `aidd-codex@aidd-codex-local` を `codex plugin remove` で外した。旧 marketplace は `~/.agents/plugins/marketplace.json` に1件だけだったため、このファイルを一時ディレクトリへ退避してから削除した。`codex plugin marketplace list` には configured 側だけが残り、`codex plugin list` は同プラグインを installed / enabled と報告した。

信頼前に `/hooks` で、出所が `Plugin - aidd-codex@aidd-codex-configured` の次の4本であることを確認した。表示された `${PLUGIN_ROOT}` の展開先は `~/.codex/plugins/cache/aidd-codex-configured/aidd-codex/0.1.0`。コマンドの形は `"${PLUGIN_ROOT}"/scripts/X`（所有権確認だけ末尾 `codex`）に一致した。

| event | script | 信頼前 |
| --- | --- | --- |
| PreToolUse | `codex-skip-marker-deny.sh` | New hook - review required |
| SessionStart | `check-branch-pr-status.sh` | New hook - review required |
| SessionStart | `check-branch-tool-ownership.sh codex` | New hook - review required |
| SessionStart | `check-local-main-freshness.sh` | New hook - review required |

利用者が段階 (4) 開始時に承認した操作として、この4本だけを `/hooks` で個別に信頼した。`config.toml` の `hooks.state` に同 plugin ID の PreToolUse 1行と SessionStart 3行が追加された。別プラグインの信頼待ち2本は信頼していない。

### 信頼前後の同一操作

信頼前後とも、同じ非公開検証用リポジトリを対象に Codex CLI `0.147.0` を新規起動した。CLI 既定の `gpt-6-sol` はこの ChatGPT アカウントで非対応のエラーになったため、操作を伴う `codex exec --json` では利用可能な `gpt-5.5` を指定した。hook 定義と CLI 版は変えていない。CLI の JSON イベントに出ない SessionStart の追加文脈は、対象セッションの保存記録にある developer message で確認した。

| 項目・同じ操作 | 信頼前 | 信頼後 |
| --- | --- | --- |
| (a) `touch .claude/.verify-state/x.skip` を Codex のシェルツールへ1回依頼 | exit 0 で作成された。比較前にそのファイルを削除 | `Command blocked by PreToolUse hook`。理由は「Codexはask未対応のためdenyに読み替え」。ファイルは存在しない |
| (b) `claude/plugin-hook-fixture` で新規セッション | 対象の警告なし | 「Claude Code 用のブランチ」と警告 |
| (c) PR #1 がマージ済みの `verify/merged-head` で新規セッション | 対象の警告なし | 「既に以下のPRでマージ済みです」と PR #1 の番号・タイトル・URL を含む警告 |
| (d) `FETCH_HEAD` を約48時間前にして新規セッション | 対象の警告なし | 「ローカルmainが古い可能性があります（前回fetchから約48時間経過（既定24時間）、ローカルmainはorigin/mainより0コミット遅れています）」と警告 |

(d) の時刻変更は、macOS の `touch -d` が受理されなかったため `touch -t` で行った。元の mtime を nanosecond 単位で保存し、各測定後に復元した。(a) は `codex exec` のコマンド呼出し記録に deny の理由が残り、モデルの説明だけを根拠にしていない。

(c)(d) は vkumai 正本の各スクリプトと配布コピーを、同じ検証ブランチ・同じ `FETCH_HEAD` 条件の cwd で直接実行した。両スクリプトの出力と、Codex セッションに注入された警告文は**それぞれバイト単位で一致**し、文言差は0だった。vkumai リポジトリ自身の Git 履歴を検証 fixture に変えてはいない。配布された判定本体5ファイルも vkumai 正本とバイト単位で一致した。

信頼後の doctor は信頼前と全行同じで、信頼状態は引き続き「不明」と報告した。doctor に実発火記録が無いため、この差分なしは設計どおり。hook プロセスを一時的な `BASH_ENV` 計測で識別すると、SessionStart 3本と PreToolUse 1本で `PLUGIN_ROOT=/Users/masanori/.codex/plugins/cache/aidd-codex-configured/aidd-codex/0.1.0`、`cwd=/Users/masanori/雑談/aidd-codex-verify` が実測された。計測用ファイルはプラグイン外の一時ディレクトリだけに置いた。

### 残る範囲

- **追試後の検査:** `bash scripts/build-plugin.sh --check` は295ファイル一致、`git diff --check` は成功。CI と同じ `scripts/*.test.sh`・`scripts/lib/*.test.sh` の全件ループは160本を実行し、159本が成功、`check-layer-consistency.test.sh` だけが失敗した。失敗は作業パスの `雑談` が `%E9%9B%91%E8%AB%87` に変換され、Node が `scan-db-constraints.mjs` を見つけられない既知のローカル環境要因。テストや生成器は変更していない。GitHub CI は更新後のコミットで別途判定する。

- **未検証:** ChatGPT desktop app での実走、symlink 導入、他の Codex CLI 版、複数リポジトリでの利用。
- 個人の configured marketplace と信頼した4本は再検証用に残した。停止する場合は `/hooks` で4本を無効化し、`codex plugin remove aidd-codex@aidd-codex-configured` と `codex plugin marketplace remove aidd-codex-configured` で導入を解除する。非公開検証用リポジトリは削除していない。
