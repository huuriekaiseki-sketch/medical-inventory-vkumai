# Part 1 — 仕様（★人間がレビューする部分）

## 何ができるようになるか

「品質チェックを打っていません」と知らせるだけの hook が、**自分の都合で失敗しなくなります**。

この hook は作業を止めない、知らせるだけのものです。ところが、記録の置き場に書き込めない環境では、hook そのものが失敗として終わります。すると Codex の画面に「hook が失敗しました」と出て、本来の知らせと区別がつきません。

Claude Code 側の同じ役割の hook は、知らせるだけで失敗しません。

## 操作の流れ

| 状態 | いま | 変更後 |
| --- | --- | --- |
| 記録の置き場に書ける | 正しく動く | 正しく動く |
| 記録の置き場に書けない（読み取り専用など） | **hook が失敗**として終わる | 失敗しない。知らせるべきことがあれば知らせる |
| ターンの終わりの確認 | 置き場を作り、古い記録を消してから確認する | **読むだけ**。何も作らず、何も消さない |

## 受け入れ条件

印の意味: ✅ スクリプト単体のテストで確認済み / ⬜ 未実施

- ✅ 記録の置き場に書けなくても、hook は失敗として終わらない
- ✅ ターンの終わりの確認は、導入先のリポジトリに**何も作らない**（フォルダも作らない）
- ✅ 記録を残す側（品質チェックを打ったとき）が書けなかった場合は、黙って終わる
- ✅ その結果「打ったのに毎回知らせが出る」ことは、既知の制約に書く
- ✅ 記録が書ける環境での動きは変わらない

## 決めてほしいこと

| # | 決めること | おすすめ | 理由 |
| --- | --- | --- | --- |
| 1 | 記録が書けないとき、「書けません」と知らせるか、黙るか | 黙る | 知らせるだけの hook が毎回別の知らせを足すと、本来の知らせが埋もれる。既知の制約に書けば足りる |
| 2 | 古い記録（7 日より前）の掃除は、記録を残す側だけが行うでよいか | はい | 確認する側を「読むだけ」にするため |

## 分かっていないこと

- 2026-09-28 の実機確認で出た「Stop hook (failed): hook exited with code 1」が、この hook によるものかどうか。**特定できていません**（あのとき本来の知らせは正しく出ていたので、別の hook の可能性が高い）。この仕様書は、その表示を消すことを約束しません

# Part 2 — 実装計画（AI 用・レビュー不要）

## 根拠（2026-09-29 実測）

| 状態 | 結果 |
| --- | --- |
| 通常（未追跡の `src/probe.ts` あり） | `codex-ai-check-suggest.sh` rc=0 |
| `CODEX_AI_CHECK_STATE_DIR` を書けない場所に向ける | rc=1 |

`set -euo pipefail` の下で `mkdir -p "$STATE_DIR"` が失敗している。`codex-ai-check-track.sh` にも同じ `mkdir -p` と、`printf … > "$STATE_DIR/…"` がある。

## 実装セット

| セット | 触るファイル | 内容 |
| --- | --- | --- |
| A | `scripts/codex-ai-check-suggest.sh` | `mkdir` と `find -delete` を削除（読むだけにする） |
| A | `scripts/codex-ai-check-track.sh` | `mkdir` と書き込みの失敗で exit 0 |
| A | `scripts/codex-ai-check.test.sh` | 書けない置き場のケースを追加 |
| 統合 | `docs/plugin/codex-vkumai/KNOWN-LIMITS.md` | 制約の追記 |

3 ファイルは 1 組なので 1 セットで進める。ほかの仕様書とファイルは重ならない。

## 方針

- suggest: `STATE_FILE` が無ければ `RECORDED_HASH=""` のまま比較へ進む（既存の動き）。置き場が無くても同じ
- track: `mkdir -p "$STATE_DIR" 2>/dev/null || exit 0`、書き込みも `|| exit 0`
- ハッシュの計算は 2 本で同じ結果になる必要がある。今回は計算に触らない（触ると「打ったのに知らせが出る」退行になる）
- `codex-ai-check.test.sh` は中心リポジトリを名指しで見るため同梱しない（既知の制約のまま）

## テスト観点

- 赤の確認: 書けない置き場で suggest が rc=1 → 直した後は rc=0
- suggest の実行前後で、リポジトリに `.codex/` が増えていないこと
- track: 書けない置き場で rc=0、記録なし
- 通常の流れ（変更 → 知らせ → チェック → 知らせが消える → さらに変更 → 知らせ）が変わらない
