- 状態: 2026-09-29 承認（決めてほしいこと 4 件はおすすめの通り）。スクリプトとテストは実装済み

# Part 1 — 仕様（★人間がレビューする部分）

## 何ができるようになるか

プラグインを入れた先のリポジトリで、警告文が**そこに無い文書を指さなくなります**。

いまの警告文は「`docs/agents/common.md` を参照」のように、vkumai の中にある文書を案内しています。vkumai では読めますが、プラグインを入れた別のリポジトリにはその文書がありません。AI が文書を探しに行って見つけられず、時間を使います。

## 対象の警告文

| # | プラグイン | 警告 | いま指している文書 |
| --- | --- | --- | --- |
| 1 | 共通 | ブランチが別のツール用 | `docs/agents/parallel-agent-work.md` |
| 2 | 共通 | ローカルの main が古い | `docs/agents/common.md` |
| 3 | 共通 | ブランチがマージ済み | `docs/agents/common.md` |
| 4 | vkumai 固有 | 依存を足すコマンド | `docs/agents/known-failure-patterns.md` |
| 5 | vkumai 固有 | `package.json` の編集 | `docs/agents/known-failure-patterns.md` |

件数: 5 つ（共通 3、vkumai 固有 2）。

## 変更後の警告文

文書への案内を外し、**警告文だけで何をすればよいかが分かる**ようにします。5 つとも、やるべきことは既に文中に書いてあるので、案内を外しても情報は減りません。

例（2 番）:

```
いま:   …`git checkout -b <new-branch> origin/main` してください（docs/agents/common.md「ブランチ運用ルール」参照）。
変更後: …`git checkout -b <new-branch> origin/main` してください。
```

## 受け入れ条件

印の意味: ✅ 確認済み / 🟡 一部 / ⬜ 未実施

- ✅ 5 つの警告文から、文書への案内が無くなっている
- ✅ 案内を外しても、警告文だけで次にやることが分かる（文末の案内を削っただけで、ほかの文言は変えていない）
- ✅ Claude Code と Codex で、同じ状況に同じ警告文が出る（同じスクリプトを通る。配布物が正本と同一であることは生成器のテストが見る）
- 🟡 配布物の中に、利用者に見える形で vkumai の文書を指している箇所が残っていないことを、検査が確かめる（**Codex 用の 2 プラグインだけ**を見る。Claude 用の 2 プラグインには、今回の 5 つ以外の hook に同じ形の案内が残っており、そちらは対象外）

## 決めてほしいこと

| # | 決めること | おすすめ | 理由 |
| --- | --- | --- | --- |
| 1 | 案内を**外す**か、文書を**一緒に配る**か | 外す | 配ると、vkumai 側で文書を直すたびに配り直しが要る。警告文は既にやることを書いている |
| 2 | vkumai 自身でも案内が消える。これでよいか | はい | 同じ部品を共有しているので、片方だけ残せない。vkumai では `CLAUDE.md` から同じ文書にたどれる |
| 3 | vkumai 固有の 2 つ（4・5 番）も対象にするか | する | vkumai 固有のプラグインも、入れる先は vkumai とは別のリポジトリ |
| 4 | 4 番の「引き継ぎメモ 00『依存の変更』に書きます」は残すか | 残す | 導入先に引き継ぎメモの決まりが無くても、害は無い。何を残すべきかの説明として意味がある |

## 対象にしないもの

- スクリプトの中の**説明書き（コメント）**が指している文書。利用者にも AI にも表示されないため
- 警告文の中の `issue #485` などの番号。止めた理由の出どころとして残す
- 「`codex/*` は Codex 用、`claude/*` は Claude Code 用」というブランチ名の決まりそのもの。導入先が別の決まりを使っている場合の扱いは、導入先が決まってから考える

## 実装セット

| セット | 触るファイル | 内容 |
| --- | --- | --- |
| A | `scripts/check-branch-tool-ownership.sh` / `scripts/check-local-main-freshness.sh` / `scripts/check-branch-pr-status.sh` と各テスト | 文言の変更 |
| 統合 | `scripts/check-dependency-change.sh` / `.test.sh` | 文言の変更（SPEC 01・02 と同じファイルなので最後） |
| 統合 | 構造テスト（新規または `check-plugin-integrity.test.sh` に追加） | 配布物の `MSG=` / `REASON=` に `docs/agents` `docs/superpowers` が無いこと |

## 方針

- 文末の `（docs/agents/…参照）` を削るだけ。ほかの文言は変えない
- 同じ 3 本は `aidd-core`（Claude 用プラグイン）にも配られているので、生成し直せば両方が変わる
- 文言に依存しているテストを先に洗う（`grep -rn "ブランチ運用ルール" scripts/*.test.sh` など）。2026-09-27 の evidence は「正本と配布物の警告文がバイト単位で一致」を記録しており、この性質は生成し直した後も保たれる
- 構造テストは**壊して落ちること**を確かめる（配布物に案内を 1 つ戻して赤くなること）

## テスト観点

- 5 つの警告文に `docs/` が含まれない
- 警告文のほかの部分（コマンドの例、件数、PR 番号）が変わらない
- 構造テストの赤の確認
- `build-plugin.sh --check` の一致
