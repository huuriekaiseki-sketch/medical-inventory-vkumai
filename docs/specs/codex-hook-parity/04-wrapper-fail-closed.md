# Part 1 — 仕様（★人間がレビューする部分）

## 何ができるようになるか

Codex 用の守りが**壊れた状態で導入されていても、素通りしなくなります**。あわせて、診断（doctor）がその壊れ方を見つけられるようになります。

Codex 用の守りは 2 つの部品の組です。

| 部品 | 役割 |
| --- | --- |
| 判定する部品 | 止めるべき操作かを決める（Claude Code と共有） |
| 読み替える部品 | 「確認」を「止める」に変える（Codex 専用） |

いまは、判定する部品が無い・動かないとき、読み替える部品は**エラーで終わるだけ**です。Codex がそのエラーを「止める」と扱うかは分かっておらず、通してしまう可能性があります。

Claude Code 側は判定する部品を直接呼ぶので、この問題はありません。

## 操作の流れ

| 状態 | いま | 変更後 |
| --- | --- | --- |
| 部品が揃っている | 正しく動く | 正しく動く |
| 判定する部品が無い | エラーで終わる（止まるかは不明） | **止まる**。理由に「部品が欠けています」と出る |
| 判定する部品が途中で失敗した | エラーで終わる（同上） | **止まる** |
| 判定する部品が読めない結果を返した | エラーで終わる（同上） | **止まる** |
| 診断を実行する | 登録の有無だけを見る | 部品のファイルがあるか・実行できるかも見る |

## 受け入れ条件

印の意味: ✅ スクリプト単体のテストで確認済み / 🟡 一部 / ⬜ 未実施

- ✅ 判定する部品が無いとき、対象のツール（コマンド実行・ファイル編集）が止まる（配布した 0.1.4 の実機で確認。2026-09-29、Codex CLI 0.147.0。`docs/plugin/codex/evidence/2026-09-29-release-0.1.4-verify.md`）
- ✅ 止めた理由に、何が欠けているかと、直し方（入れ直す）が書いてある
- ✅ 部品が揃っているときの動きは変わらない
- ✅ 診断が、部品ごとに「ある／無い／実行できない」を 1 行ずつ出す
- ✅ 診断は引き続き「信頼済み」「動いた」とは言わない（分からないことは分からないと言う）

## 決めてほしいこと

| # | 決めること | おすすめ | 理由 |
| --- | --- | --- | --- |
| 1 | 部品が壊れているとき、**全部のコマンドとファイル編集が止まる**。これでよいか | はい | 守りが効いていないまま作業が進むより、止まって気づくほうがよい。`jq` が無いときは既にこの扱い |
| 2 | 診断の対象に `aidd-codex-vkumai` の部品も入れるか | 今回は入れない | 診断は `aidd-codex` の中にあり、別のプラグインの中身を見に行く形になる。既知の制約に書いてある通りのまま |

# Part 2 — 実装計画（AI 用・レビュー不要）

## 根拠（2026-09-29 実測）

`codex-skip-marker-deny.sh` だけを別の場所に置いて実行 → rc=127、出力は JSON でない。`set -euo pipefail` の下で `OUT="$(… | bash "$GUARD")"` が失敗して、そのまま抜けている。

## 実装セット

| セット | 触るファイル | 内容 |
| --- | --- | --- |
| A | `scripts/codex-skip-marker-deny.sh` / `scripts/codex-dependency-change-deny.sh` とテスト | fail-closed 化 |
| B | `scripts/aidd-codex-doctor.sh` / `.test.sh` | 部品の存在と実行ビットの確認 |

A と B は別ファイルなので同時に進められる。SPEC 01 とも別ファイル。

## 方針

- A: 次の 3 つを exit 2 + stderr に理由、に統一する
  1. `$GUARD` が無い・読めない
  2. `$GUARD` の終了コードが 0 以外（2 はそのまま 2）
  3. `$GUARD` の出力が空でなく、かつ JSON として読めない
- A: ラッパー 2 本は同じ形なので、変更も同じ形にする
- B: `HOOK_NAMES` の各スクリプトについて `[ -f ]` と `[ -x ]` を見る。`codex-skip-marker-deny.sh` は相方の `check-skip-marker-write.sh` も見る。出力は `部品 <name>: あり／なし／実行不可`
- B: 「判定」行の `missing` に「部品なし」「実行不可」を足す

## テスト観点

- 赤の確認: 相方欠落で rc=127 → 直した後は rc=2
- 相方が exit 1 / exit 2 / 非 JSON 出力を返す stub での rc=2
- 相方が沈黙 → ラッパーも沈黙で rc=0（対照）
- doctor: 実行ビットを外した部品、消した部品、相方だけ消した場合
- doctor: 既存の「保護済み・実発火と言わない」検査が通る
